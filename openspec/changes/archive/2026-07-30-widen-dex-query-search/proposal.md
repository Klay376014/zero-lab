## Problem

搜尋框的佔位字寫著「名稱 / 編號 / 屬性 / 形態」，但實際上**只比對物種的中英文名**。四件承諾裡三件做不到：

- 搜 `475` 得到零結果（艾路雷朵的編號）
- 搜 `dragon` 或 `龍` 得到零結果（屬性要用屬性鈕才篩得到）
- 搜 `mega` 或 `超級` 得到零結果（形態標籤）

還有兩個同源缺口：**多詞搜尋不成立**（`mega charizard` 因為整串被當成一個子字串而落空），以及**卡片不會顯示查詢命中的那個形態**（搜 `mega charizard x` 顯示的仍是基本形態的圖，即使查詢明確指名了 Mega X）。

這使得 208 筆的網格只能用名稱抵達。編號是這份介面自己在每張卡片左上角印出來的東西，卻不能用它搜尋。

## Root Cause

兩層各有一半原因，**實作沒有偏離規格 —— 是規格比設計稿窄**。

設計稿把搜尋語料建成一個 haystack，含九類欄位並逐詞比對：中英物種名、中文分類、編號（原始與四位補零兩種寫法）、世代（`gen5` 與羅馬數字兩種寫法）、所有形態的中英標籤、所有形態的屬性（英文與中文）。它另外用形態標籤的命中決定卡片顯示哪一個形態。

移植第二批（`port-champions-dex-grid`）為搜尋立的需求叫「Search matches across both languages at all times」，內容只涵蓋**物種名**的跨語系比對。實作照該需求寫成兩個欄位、單一子字串，所以既有的驗收與 spec 檢查都不會抓到 —— 缺的東西從來沒有被要求過。

佔位字則是從設計稿的 I18N 表**原樣搬過來的**，於是它描述的是設計稿的行為而不是移植版的行為。字串與需求兩邊分別正確，合起來就成了一個承諾與實作不符的介面。

## Proposed Solution

把搜尋語料擴充成設計稿的九類欄位，並補上逐詞比對與查詢驅動的形態選擇：

- 搜尋改為比對一個 haystack，含中英物種名、中文分類、編號（原始與四位補零）、世代（`gen<n>` 一種寫法）、每個形態的中英標籤、以及跨全部形態的屬性英文名與中文名
- **刻意不收錄設計稿的裸羅馬數字世代 token。** 設計稿的 haystack 含 `GEN_ROMAN[sp.g]`，於是搜 `V` 會命中 208 筆裡的 125 筆 —— 任何名稱含字母 v 的物種（Venusaur、Vileplume、Vaporeon…）。單字母 token 命中六成資料集，與「搜尋壞了」無法區分。`gen5` 沒有這個問題，保留它
- 空白分隔的多個詞**全部**都要命中才算命中，逐詞獨立比對而非整串子字串
- 卡片顯示的形態改為：查詢命中某個形態的標籤時顯示該形態；否則沿用既有的屬性篩選判定；兩者都沒有則顯示基本形態
- 佔位字不動 —— 修好之後它描述的就是實際行為

屬性鈕與世代鈕**不動**。搜尋能打到屬性不是要取代篩選鈕，而是因為佔位字承諾了它，而且打字比在十八顆鈕裡找一顆快。

## Non-Goals

- **不動排序、屬性鈕、世代鈕、重設鈕。** 本批只碰搜尋字串的比對範圍與卡片形態的選擇
- **不加模糊比對或拼字容錯。** 逐詞子字串是設計稿的行為，也是可預測的行為
- **不加搜尋語法**（欄位前綴、引號片語、排除詞）。設計稿沒有，而 208 筆的集合不需要
- **不做防抖或索引。** 既有需求已載明 208 筆每次按鍵全量重算是刻意的，語料變寬不改變那個判斷
- **不改招式表。** 招式表有自己的排序與篩選，與網格查詢互不相干

## Capabilities

### Modified Capabilities

- `dex-query`: 「搜尋跨兩個語系比對」這條需求的範圍從物種名擴充為九類欄位並加上逐詞比對；「結果與命中形態配對」這條需求增加「查詢命中形態標籤時卡片顯示該形態」

## Success Criteria

- 搜 `475` 與 `0475` 都只命中艾路雷朵（1 筆）；搜 `740` 只命中好勝毛蟹
- 搜 `dragon` 命中 19 筆，且該組**等於**屬性鈕選 Dragon 的結果集
- 搜 `龍` 命中 25 筆 —— 那 19 筆加上六筆中文名含「龍」但不是龍屬性的物種（暴鯉龍、化石翼龍、戰槌龍、護城龍、龍頭地鼠、冰雪巨龍）。**這是子字串比對的正確結果，不是缺陷**：屬性中文名與物種中文名在同一個語料裡，而部分名稱比對是既有需求
- 搜 `mega` 與 `超級` 各命中 73 筆物種（75 個 Mega 形態分佈在 73 個物種上，噴火龍與超夢各有兩個），且兩組相同並等於「帶 Mega 形態的物種」
- 搜 `mega charizard` 命中噴火龍 1 筆，且卡片顯示的是 Mega 形態而非基本形態
- 搜 `gen5` 命中 29 筆，且該組等於世代鈕選 5 的結果集
- 搜 `alola` 與 `阿羅拉` 各命中 2 筆（雷丘、九尾）；搜 `火焰寶可夢` 命中 2 筆（噴火龍、烈焰猴）
- 既有行為不回歸：`charizard`、`CHARIZARD`、`噴火龍`、`char`、`噴火` 仍各自命中噴火龍，`ditto` 仍不命中；切換主導語系不改變任何結果集
- `pnpm run check` 與 `npm exec tsc -- --noEmit -p src/tsconfig.json` 皆通過
