## Context

三項篩選能力要補回設計稿的行為：屬性多選、`★ 僅 MEGA`、`僅多形態`。

現況四點決定了下面的做法：

- `typeFilter` 是 `TypeName | null`，被 `matchesType()`、`matchingFormIndex()`、`resetQuery()` 與 `QueryBar.vue` 的選中判斷四處讀取。改變它的形狀會同時觸及這四處
- **這個專案從未把 `Set` 或 `Map` 放進響應式狀態。** `src/` 裡的集合全是非響應式的快取（`dex.ts` 的 `typesBySpecies`、`TypeGlyph.vue` 的 `cache`）或區域運算（`LearnsetTable.vue` 的 `own`）。集合代理的響應式行為在這個平台上一次也沒被驗證過
- `src/state/learnset.ts` 的 `bonusOnly = ref(false)` 是布林篩選鈕的現成前例，兩顆新鈕照它走
- 查詢列的第二列刻意把「屬性」標籤放在換行容器**外**，因為標籤放在容器內會吃掉第一行的寬度，18 個格子會斷成 8+10 而不是 9+9。新增第三列不得干擾這件事

## Goals / Non-Goals

**Goals**

- 屬性可同時選多個，語意為 OR
- 兩顆布林篩選鈕，與其他篩選之間為 AND
- 卡片顯示的形態與「哪個條件命中」保持一致
- 第三列的加入不改變第二列 18 個格子的 9+9 斷行

**Non-Goals**

- 不加世代篩選、不加第三種排序、不改搜尋語料、不加無障礙屬性、不做兩顆新鈕的互斥。理由見 proposal 的 Non-Goals

## Decisions

### 決定一：屬性篩選存成唯讀陣列並整份取代，不用響應式 `Set`

`typeFilter` 改為 `ref<readonly TypeName[]>([])`。切換一個屬性的寫法是產生新陣列再整份指派，不是在原地 `add`／`delete`。

**替代方案**：`ref(new Set<TypeName>())` 並原地增刪。**不採用的理由**：這個專案沒有任何一處把集合放進響應式狀態，所以「集合代理會不會觸發更新」在這個平台上是未驗證的。而它的失敗形狀正是 §12.17 那一類 —— 宣告寫得下去、不報錯、`add()` 成功了，畫面就是不更新。整份取代不依賴任何集合代理，18 個成員的複製成本可以忽略，且與專案其他狀態的更新方式一致。

**這不是在斷言平台的集合響應式壞掉** —— 沒有量過。要用它就要先量，而本次沒有理由付那個成本。

**命名一併改。** `typeFilter` 改名為 `typeFilters`（複數），因為留著單數名字承載一個集合，正是讓下一個人誤讀成單選的原因。

### 決定二：兩顆布林篩選鈕各自一個 `ref(false)`

`megaOnly` 與 `multiOnly` 兩個獨立的 `ref(false)`，照 `learnset.ts` 的 `bonusOnly` 前例。

**替代方案**：合成一個旗標物件或一個「啟用中的特殊篩選」集合。**不採用的理由**：兩者語意無關（一個問有沒有 Mega，一個問形態數），合併只會製造一個沒有意義的中間概念，而且又把集合帶回響應式狀態。

### 決定三：篩選之間 AND，屬性內部 OR

結果集的判定是四個條件的 AND：搜尋、屬性、Mega、多形態。屬性條件內部才是 OR（物種的任一形態帶有任一選中屬性）。

這與既有需求「搜尋與屬性篩選同時成立才入選」一致，也與設計稿 `match()` 相同。**選火＋水是「火系或水系」而不是「同時是火與水」** —— 後者會讓大多數組合是零結果，那會讓第二次點選幾乎總是把畫面清空。

### 決定四：形態選擇規則從四條變五條，Mega 分支排在屬性之後

規則順序：具名形態 → 具名屬性 → 屬性篩選（任一命中）→ `★ 僅 MEGA` 命中則第一個 Mega 形態 → 基本形態。

第三條從「第一個帶有選中屬性的形態」改為「第一個帶有**任一**選中屬性的形態」。第四條是新增的，位置與設計稿 `formFor()` 一致（`state.types` 分支之後、`return 0` 之前）。

**為什麼 Mega 分支要排在屬性之後而不是之前**：屬性篩選是讀者明確指定的屬性，Mega 只是一個布林開關。當兩者都開啟時，讓卡片回答那個更具體的條件。

### 決定五：第三列是獨立的 `QueryRow`，不塞進第二列

第三列用與前兩列相同的 `QueryRow` 類別，內含兩顆 `Chip`。

**替代方案**：把兩顆鈕接在第二列屬性容器之後。**不採用的理由**：第二列的斷行是容器獨有的性質（標籤刻意放在容器外就是為了這件事）。在同一列尾端追加任何東西，都會讓 18 個格子的 9+9 斷行變成未知數，而那是既有需求明文要求的版面。獨立一列讓兩者互不影響。

**代價已在 proposal 記錄**：spec 兩度用「一列的垂直空間比篩選本身值錢」拒絕增加列數。本次是重新權衡後的決定，不是忽略。

## Implementation Contract

**In scope**：`src/state/query.ts`（狀態形狀、篩選、形態選擇、重設）、`src/components/QueryBar.vue`（第三列與多選判斷）、`src/data/i18n.ts`（兩個新鍵）、`src/App.css`（若第三列需要新規則）。

**Out of scope**：`src/data/dex.ts`（資料層不動）、`src/components/DexGrid.vue`、`src/components/SpeciesCard.vue`、排序邏輯、搜尋語料。

**狀態契約**

| 名稱 | 型別 | 初始值 |
|---|---|---|
| `search` | `string` | `''` |
| `typeFilters` | `readonly TypeName[]` | `[]` |
| `megaOnly` | `boolean` | `false` |
| `multiOnly` | `boolean` | `false` |
| `sortOrder` | `SortOrder` | `SORT_ORDERS[0]` |

五者互相獨立，各自可設定而不擾動其餘四者。重設把五者全部回到初始值。

**篩選契約**：物種入選的條件是下列四項全部成立。

| 條件 | 何時成立 |
|---|---|
| 搜尋 | 沒有搜尋字串，或物種的語料包含全部 token |
| 屬性 | `typeFilters` 為空，或物種的任一形態帶有 `typeFilters` 中的**任一**屬性 |
| Mega | `megaOnly` 為假，或物種有至少一個 Mega 形態 |
| 多形態 | `multiOnly` 為假，或物種的形態數大於一 |

**形態選擇契約**：五條規則，第一個產生結果的勝出 —— 具名形態、具名屬性、任一選中屬性、`megaOnly` 開啟時的第一個 Mega 形態、基本形態。

**驗收條件**

1. 未選任何屬性時，結果與現在完全相同（208 筆）
2. 只選一個屬性時，結果與改動前的單選完全相同 —— **這是回歸的判準**，多選不得改變單選的行為
3. 同時選火與水，結果筆數等於「火系筆數 ＋ 水系筆數 − 兩者皆有的筆數」，且大於任一單選的筆數
4. 再次點擊已選中的屬性會取消它；取消最後一個屬性後結果回到 208 筆
5. `★ 僅 MEGA` 單獨開啟時，結果中每一筆都有 Mega 形態；`僅多形態` 單獨開啟時，每一筆的形態數大於一
6. 兩顆同時開啟時，結果是兩個條件都成立的物種，筆數不大於任一單獨開啟
7. `★ 僅 MEGA` 開啟且未選屬性時，卡片顯示的是 Mega 形態而非基本形態
8. 清除篩選把五項狀態全部歸零，結果回到 208 筆
9. 第二列的 18 個屬性格仍是 9+9 斷行，未因第三列而改變
10. `pnpm run check` 與 `npm exec tsc -- --noEmit -p src/tsconfig.json` 均為 exit 0
11. 裝置驗收：iOS 實機，三列都完整可見不被裁切，兩顆新鈕的選中態在兩個模式下都看得出來

**失敗模式**：若誤用了原地增刪的集合，症狀是點了屬性格但畫面完全沒反應 —— 不報錯。判別方式是看結果筆數有沒有變，不是看有沒有錯誤訊息。

## Risks / Trade-offs

- **第三列吃掉卡片網格的垂直空間** → 已知且已接受，代價記在 proposal。若實機上覺得過重，退路是把兩顆鈕改成與排序晶片同列（會壓縮搜尋框），而不是刪掉功能
- **選中態在 POCKET 模式下難以分辨** → 屬性格已有這個問題並用背景色而非邊框解決（`chipBackground` 的註解記著 POCKET 的 accent 與 line 同色）。兩顆新鈕沿用 `ChipOn` 的既有選中樣式，不自創第三種
- **`typeFilter` 改名會波及所有引用處** → 改名仍是刻意的（留著單數名字承載集合更危險），但**原本寫在這裡的「`tsc` 會擋下遺漏」是錯的，實作時當場證偽**：`vue-tsc` 未安裝，`npm exec tsc` 看不懂 `.vue`，所以改名後 `QueryBar.vue` 四處失效引用照樣 exit 0。實際靠的是 `pnpm run build`（會編譯 `.vue`）加上逐處人工核對。這件事已記入 ROADMAP B 節
