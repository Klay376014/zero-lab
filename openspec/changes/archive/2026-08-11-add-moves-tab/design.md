## Context

移植版目前只有一個畫面軸：網格 → 物種詳情 → 學習者清單。招式在這條軸上只是詳情面板裡的一列，資料集也只帶了名稱與六個數值欄位。這個 change 加入第二條軸（招式分頁 → 招式詳情 → 學習者清單），並補上讓那條軸有意義所需的資料。

討論期間對上游來源做過量測，結論決定了本設計的大部分形狀，全部列在下面，因為它們無法從程式碼反推：

**招式的 flag 與說明文字在 Champions 的來源裡不存在。** Bulbapedia 的 learnlist/champ 一列只吐出名稱、屬性、傷害類別、威力、命中、PP 與一個本系加成標記，招式機制的解析器就是照這個形狀寫的。唯一可得的來源是 PokeAPI 與 52poke，兩者描述的都是本傳。

**Champions 重調了八成招式的數值。** 逐筆比對 496 個招式的威力／命中／PP，**401 個與本傳不同**（大爆炸 5→8、地震 10→12、飛葉快刀 30→20）。招式聚合腳本開頭那句「Champions retunes some values, so the game's own numbers are authoritative here」不是保守說法。

**52poke 招式列表能供應 496/496 的中文說明。** 該頁是一張欄位為「編號／中文名／日文名／英文名／屬性／分類／威力／命中／ＰＰ／說明」的表，920 列全部有說明，且「編號」就是 PokeAPI 的 move id，所以 join 走數字而非名稱。取得需要瀏覽器 User-Agent 標頭，否則回 403。文字為單行，無遊戲內換行。長度中位數 26 字、p90 34 字、最長 46 字。

**PokeAPI 的中文說明有缺口，52poke 沒有。** PokeAPI 的 move_flavor_text 的 zh-Hant 只到 version group 20（劍盾），496 個招式裡有 53 個第九世代招式沒有中文；52poke 把這 53 個全部補上。move_effect_prose 只有英文與法文，完全沒有中文。

**現行資料集有 8 個招式的中文名是簡體字**：憤怒之拳、蟲撲、大憤慨、鎧農炮、冰山風、雙光束、晶光轉轉、噴射拳，八筆全是第九世代招式，來自 PokeAPI zh-Hant 欄位在該世代的污染，其中「虫撲」是簡繁混雜。樣式檢查把 CJK 排除在字型子集檢查之外（中文走系統字型），所以沒有任何檢查會抓到。

**這 8 筆是殘留，不是全部——管線重跑會變回 33 筆。** 實作期間量到：以快取的 PokeAPI move_names.csv 重新產生資料集，有 33 個招式名是簡體。差額 25 筆是 commit e634af9（2026-08-05，「fix: 修正招式簡體文字」）直接手改 `src/data/dex.json` 與 `design/champions-dex.json` 的結果——該 commit 沒有動到 `design/pipeline/` 任何檔案。這正是 Dataset provenance 明文禁止的手編，而它的代價是隱形的：資料集檔案是對的，但管線的產出不是，所以下一次 `./run.sh` 會靜默地把那 25 筆倒回簡體。

改以 52poke 的 `/zh-hant/` 變體為名稱來源之後，這件事被修在管線裡而不是修在產物裡：重跑不再重新引入簡體，那個手編也不再需要。這是本決策除了說明文字覆蓋率之外的第二個理由。

**兩個原本沒有中文名的招式會被補上。** Syrup Bomb 與 Matcha Gotcha 在 PokeAPI 的 zh-Hant 欄位是空的，52poke 分別供應「糖漿炸彈」與「刷刷茶炮」，所以改用 52poke 之後 496/496 全部有中文名。move-index 與 move-detail 因此不需要「中文名缺失時回退英文名」這條規則——該規則只留在 learnset-table，它原本被繼承的地方。

**21 種 flag 涵蓋 425/496 個招式，71 個招式零 flag。** 其中 protect 與 mirror 各覆蓋約 340 個（近七成），non-sky-battle 與 distance 描述的是 Champions 沒有的對戰機制。flag 的中文標籤在上游完全不存在（move_flag_prose 的 zh-Hant 為 0 列）。71 個零 flag 的招式幾乎都是第八、九世代新招——是上游沒填，不是這些招式真的沒有那些性質。

**資料集體積：195 KB → 297 KB（+102 KB / +52%）**，其中 flag 僅約 2 KB，其餘是兩語系的說明文字。

**masthead 的四個規模計數目前沒有被渲染。** 提案曾交付它（commit bc97f69），一次手動 UI 調整（commit c617a76）把 template 裡的元素移除，留下一個沒人使用的 computed 與四條死樣式規則。三道檢查都看不到：樣式檢查讀樣式表不讀元素樹、vue-tsc 不為未使用的 computed 報錯、測試不碰元素樹。使用者決定移除而非復原。

## Goals / Non-Goals

**Goals:**

- 讓 496 個招式成為可瀏覽的內容，而不只是詳情面板裡的列
- 讓每個招式帶有雙語說明文字，且中文側零缺口
- 讓學習者清單有一個不需要先選定物種就能到達的入口
- 讓畫面堆疊有一條可驗證的上界規則，使反覆穿梭不會累積層
- 修正 8 筆簡體中文招式名
- 讓資料層備妥 flag，供後續決定顯示範圍

**Non-Goals:**

- **不顯示 flag。** 這一批只把 flag 存進資料層。顯示哪幾種、中文標籤怎麼寫、零 flag 的招式怎麼呈現，都留到後續 change
- **不取 52poke 的機制數值。** 威力、命中、PP、屬性、傷害類別一律維持 Champions 來源
- **不引入漢堡選單。** 為了到達一個分頁而先開一層畫面，與本設計的堆疊目標相反
- **不做招式分頁的查詢列。** 招式清單這一批不帶搜尋、篩選或排序
- **不復原 masthead 的四個規模計數**
- **不把圖鑑分頁改成路由式導航。** 那會重寫 species-detail 與 move-learners 兩份已交付的 spec
- **不引入 vue-router**（理由見下方決策）

## Decisions

### 中文說明改以 52poke 為來源，英文說明取自 PokeAPI

中文說明與中文名皆改讀 52poke 招式列表，以 move id join。英文說明取 PokeAPI move_flavor_text 中 language_id 為英文、version group 最大的一筆，並把遊戲內換行正規化為單一空白。

替代方案與否決理由：PokeAPI 的 move_flavor_text 中文側缺 53 個第九世代招式，會讓中文讀者在最新的招式上看到空白；move_effect_prose 完全沒有中文，且文字含 effect_chance 樣板需要展開。52poke 一次解決覆蓋率、文字品質與 join 穩定度三件事。

中文名改以 52poke 為準是此決策的附帶結果，也是 8 筆簡體名的修正途徑——同一個 join，不需要第二段程式。

### 外部來源只供文字，不供機制數值

管線在寫入招式表之前，SHALL 比對 52poke 的威力／命中／PP 與 Champions 既有值，並且**不得**以前者覆寫後者。既有的機制欄位維持由 Bulbapedia Champions 表供應。

這條要落成程式碼裡的斷言而不是註解：401/496 的差異意味著任何一次「順手也把數值一起更新」的修改都會靜默地把八成招式改成別的遊戲的數值，而資料集的載入期不變式只檢查筆數，不檢查數值。

### flag 只進資料層，這一批不顯示

Move 記錄新增 flag 編號陣列，零 flag 的招式省略該鍵。21 種 flag 的中文標籤不寫入資料集——它們是 UI 字串，歸字串表所有，而資料集的 provenance 要求禁止手寫內容。

替代方案與否決理由：直接全部顯示會讓每個招式詳情都掛著 protect 與 mirror 兩顆近乎無資訊的標籤（各覆蓋七成），並且對 71 個零 flag 的招式做出「這些招式沒有這些性質」的錯誤斷言——資料只支持「上游沒填」。顯示範圍需要一次獨立的取捨。

### 招式列改為開啟招式詳情

詳情面板裡的招式列，tap 目標從學習者清單改為招式詳情；學習者清單改為只從招式詳情進入。

替代方案與否決理由：維持招式列直達學習者清單、招式詳情只從招式分頁進入，會讓同一個概念（點一個招式）在兩處去到不同畫面，並且讓讀者在詳情面板看到某招式想知道它做什麼時無路可走——只能記住名字再切到招式分頁去找。多一層 tap 的代價由下一條決策的回捲規則吸收。

### 每種層最多一個實例，重入即回捲

層共三種：物種詳情、招式詳情、學習者清單。開啟一個已經在堆疊裡的層，是回捲到該層並換掉它的內容，不是再推一層。堆疊深度因此恆不超過三。

這條把 move-learners 既有的兩條規則（選擇學習者取代選取而非堆疊、關閉後回到網格而非回到來源物種）從特例推廣為通則，兩條原有行為在新規則下逐字成立。沒有這條規則，選項 A 會讓物種→招式→學習者→物種形成一個無界的環。

### 分頁控制項畫在機殼上

兩顆分頁控制項置於螢幕容器之外、機殼容器之內，沿用既有的晶片樣式與其選中態（選中為填色而非邊框，因為 POCKET 模式把強調色與線色解析為同一色調）。

替代方案與否決理由：放進螢幕內的標題列可省下約 26px 高度，但會讓分頁控制項與模式／語系兩顆晶片混在同一個視覺家族，讀者需多花一眼分辨哪兩顆會換畫面。機殼方案讓「換畫面」與「換模式」落在兩個實體層級上，而該區分是真實的。機殼容器目前只貢獻一圈顏色，是閒置表面。平台唯一允許的按壓回饋是位移而非顏色變化，在畫成實體鍵的控制項上讀作鍵程。

晶片自帶背景色，所以文字所踩的表面不因搬到機殼而改變，對比檢查不需新增受測配對。

### 分頁與層堆疊由自有 state 模組承載，不引入 vue-router

分頁以一個持有作用中分頁的 state 模組表示；層堆疊以另一個持有層陣列的 state 模組表示。

替代方案與否決理由：曾考慮 vue-router。建置外掛會把 vue 別名指向 vue-lynx，所以路由套件不會拿到第二份 runtime，這條技術阻礙不成立。但回捲規則要的是「回捲到名為 X 的層」，而路由歷史是線性位置串，只有相對位移；深度差終究要自己算，歷史因此不提供任何幫助。兩個互斥分頁本身也不需要路由。引入它會新增一個未在此平台量測過的相依，違反本專案「宣告了不等於有作用」的既有教訓。

若日後需要深連結或多步返回，重新評估的條件是：出現第二個以上需要被外部定址的畫面。

### 移除 masthead 的四個規模計數

刪除相關 Requirement 與其 Example 表，並修正另一條 Requirement 中提及四個計數的條文與情境。程式碼側刪除未使用的 computed、四條死樣式規則，以及字串表中對應的四個鍵。

理由記入 ROADMAP 的「已確認不做」節是必要步驟而非收尾：ROADMAP 自身載明「字串表少了某個鍵，是該功能沒被做的最快指標」，刪鍵之後若無紀錄，下一位讀者會判斷成功能漏失並補回。

## Implementation Contract

**In scope**：管線新增一個上游來源與三個招式欄位；資料層型別擴充；分頁與層堆疊兩個 state 模組；機殼分頁控制項、招式清單、招式詳情三個新元件；招式列的 tap 目標變更；學習者清單新增入口；masthead 四個計數的移除（spec、程式碼、字串表、ROADMAP 四處）。

**Out of scope**：flag 的任何顯示；招式分頁的查詢控制項；圖鑑分頁改為路由式導航；學習者清單本身的版面與視窗化行為（維持既有）。

### 資料形狀

招式記錄新增三個欄位：中文說明（字串，496/496 非空）、英文說明（字串，496/496 非空）、flag 編號（唯讀數字陣列，升冪；零 flag 的招式省略此鍵而非寫入空陣列）。既有七個欄位不變。

### 管線行為

新增的取得步驟以瀏覽器 User-Agent 標頭抓取 52poke 招式列表並快取於管線目錄，與既有取得腳本同樣具冪等性（已存在則略過）。聚合步驟以 move id join，對每個 Champions 招式取出中文名與說明。

驗收：重跑整條管線後，設計文件的資料集與應用資料集兩者內容一致，且應用資料集約為 297 KB。招式表中不含中文說明的筆數為 0，不含英文說明的筆數為 0。

**失敗模式**：若 join 後有任何 Champions 招式取不到中文說明，管線 SHALL 以非零狀態結束並列出缺漏的招式名，而非寫出帶空字串的資料集。這與既有各階段「自我斷言、違反即非零退出」的作法一致。

**機制數值保護**：聚合步驟 SHALL 斷言自身寫出的威力／命中／PP 與 Champions 解析結果相同。此斷言在 52poke 數值與 Champions 不同時仍須通過——它檢查的是「沒有被覆寫」，不是「兩者相等」。

### 分頁行為

作用中分頁為圖鑑或招式二者之一，初始為圖鑑。切換分頁 SHALL NOT 改變任何層的內容，也 SHALL NOT 清空層堆疊。兩顆控制項恆常可見，作用中者以填色表示。

驗收：切到招式分頁再切回圖鑑，網格的查詢條件、排序與捲動位置不變。

### 層堆疊行為

堆疊持有零到三個層，每種層至多一個實例。開啟某層時：若該層不在堆疊中則推入；若已在堆疊中，則捨棄其之後的所有層並以新內容取代該層。關閉最上層 SHALL 只移除該層。

驗收（可由狀態模組直接驅動，無需元素樹）：
- 自物種詳情開啟招式詳情、再開啟學習者清單、再選擇一個學習者後，堆疊深度為 1 且其唯一成員為物種詳情
- 自招式分頁開啟招式詳情、開啟學習者清單、選擇學習者、再從該物種開啟一個招式後，堆疊深度為 1 且其唯一成員為招式詳情
- 連續執行上述循環十次後，堆疊深度仍不超過 3
- 開啟物種詳情、開啟招式詳情、關閉招式詳情後，物種詳情仍在堆疊中且內容未變

既有 move-learners 的兩條行為在新規則下必須仍然成立，並以既有措辭驗證：選擇學習者後顯示該物種、學習者清單關閉；開啟物種 A、開啟招式、選擇物種 B、關閉詳情後顯示網格而非物種 A。

### 招式清單行為

列出全部 496 個招式。每列陳述招式名（依作用中語言）、屬性標記、傷害類別與三個數值欄位。僅具現可視範圍加緩衝的列，其餘範圍以間隔物維持捲動範圍，套用既有的可視範圍視窗能力。列高必須加入既有的列高檢查腳本，使樣式表與宣告值不一致時被檢查抓到。

驗收：於實機自第一列捲到最後一列，無空白列、無錯配（某招式的名稱配到另一招式的數值）。

### 招式詳情行為

陳述招式名（雙語）、屬性、傷害類別、威力、命中、PP 與說明文字。無固定傷害的招式其威力欄、必中招式其命中欄以破折號呈現，與招式表既有處理一致。說明文字依作用中語言切換。提供一個進入該招式學習者清單的控制項，並陳述學習者數量。

**刻意不呈現**：flag。資料存在但這一批不顯示。

驗收：切換語系後說明文字改用另一語言；496 個招式中不存在說明文字為空的情形。

### masthead 移除的驗收

字串表不再含四個規模計數的鍵；樣式表不再含四條對應規則；應用根元件不再含未使用的計數 computed；ROADMAP 的「已確認不做」節新增一列載明理由與位置。四項檢查與型別檢查全數通過。

## Risks / Trade-offs

- **[說明文字描述本傳，數值來自 Champions]** → 兩者在同一個畫面上並置，而 401/496 的數值差異意味著說明中若提及次數或倍率，可能與該遊戲的實際行為不符。緩解：說明文字絕大多數不引數值；此張力記入本文件，且既有 spec 已要求 footer 不得宣稱資料來源，故不在畫面上做來源聲明。若日後出現讀者回報的具體不符案例，重新評估是否需要在招式詳情加一句限定語。
- **[新增第三個上游來源，且該來源需要瀏覽器標頭]** → 52poke 若改變頁面結構或封鎖存取，管線的取得步驟會失敗。緩解：取得步驟具冪等性且快取於管線目錄，既有快取存在時不重抓；解析失敗時以非零狀態結束並指出解析到的列數，而非寫出殘缺資料集。
