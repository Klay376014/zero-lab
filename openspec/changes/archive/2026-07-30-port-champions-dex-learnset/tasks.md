## 2. 招式表的計算層

- [x] 2.1 在 `src/components/LearnsetTable.vue` 的 script 區實作本系加成判定，讓「Same-type attack bonus excludes status moves and follows the displayed form's types」成立：一筆招式被標記的條件是型別屬於**當前形態**的型別集合**且**傷害類別不是變化；型別集合取自傳入的形態而非物種。依 design.md 的「本系加成排除變化招式，並隨形態重算」，Mega 沿用基本形態的學習表但型別可能改變，所以同一份學習表在不同形態下要得到不同的本系集合。驗證：以腳本對資料集實算噴火龍（#6，三個形態共用一段 72 招的學習表）—— 基本形態與 Mega Y（火／飛行）各 19 筆、Mega X（火／龍）20 筆；同型別的變化招式（基本形態的 Sunny Day、Will-O-Wisp、Roost）**皆未**被標記。
- [x] 2.2 實作三種排序的比較函式，讓「Sort order is a closed set of three, each resolving ties by name」成立：名稱依主導語系字串遞增；威力高到低且無威力值者一律排在最後；屬性依 `src/data/types.ts` 既有的 `TYPE_ORDER`；**威力與屬性在值相等時一律以名稱遞增為次序鍵**。依 design.md 的「排序集合為名稱、威力、屬性三種，每種都以名稱作為次序鍵」—— 沒有次序鍵的等值列次序是實作定義的，而威力欄有大量等值。驗證：以腳本對噴火龍學習表實算，威力排序下任兩相鄰列滿足「威力非遞增，且威力相等時名稱遞增」；spec 的 Example 逐項通過（Focus Punch、Giga Impact、Hyper Beam 三筆 150 依名稱排，Crunch、Dig、Dragon Claw 三筆 80 依名稱排，無威力的 Beat Up 在最後）。
