主題選單的疊層

選單掛在 masthead 裡的時候，查詢列會畫在它上面——查詢列是 .Screen 裡比較後面的兄弟節點， 而這個移植版的疊層一路都只靠 document order（src/App.css 零處 z-index）。 三種解法都做出來跑過了，下面是同一個 app、同一次按下模式鈕的實際畫面。

三種做法 SAME PRESS, THREE ARRANGEMENTS

都是 POCKET 下按一次模式鈕的樣子。橘框是我的建議。

A · 覆蓋層面板

建議 · 零未量測依賴

  • 位置是樣式表既有的字面值：left:21px top:21px（機身 9 + 螢幕 12）。沒有量測常數。
  • 畫在 .Root 的覆蓋層帶，和詳細頁面板同一層——這是本專案唯一量過的絕對定位。
  • 「點外面關閉」順便成立（攔截層排在選單前面）。已實測：點卡片會關選單且不會把卡片點開。
  • 視覺上不是下拉，是一塊蓋住標題左上角的面板；和觸發鈕的位置沒有視覺連線。
  • spec 要改一句 anchored to that trigger 的措辭。

B · 落在 masthead 列下方

折衷 · 一個量測常數

  • 比較像下拉，位置在標題列下面。
  • top:83px 是量測值：那一列的位置由標題與副標的行高決定，樣式表沒宣告，平台自己決定。換裝置或字型會失準。
  • 橫向不能對齊觸發鈕：鈕的 x 在結果數字後面，而「208 / 208 種類」的寬度會隨數字與語言改變。所以只能靠螢幕左緣，看起來是從副標下面掉出來的。

C · 掛在鈕下方 + z-index

最好看 · 押未量測行為

  • 就是一般人想像的下拉：從鈕底下掉出來，橫向自動對齊。
  • 靠 z-index:10。src/App.css 目前零處 z-index，這個平台沒量過。上圖是 web preview，而 web 通了不代表 iOS 通——那正是 §12 反覆記錄的失敗形狀：宣告被接受、行為不發生。
  • 失敗時的樣子就是本頁最上面說的那個：選單被查詢列吃掉一半。
  • 攔截層做不出來（排在後面會吃掉選單列的點擊），所以只能靠再按一次鈕關閉。

順帶一提，EMERALD 本身跑起來了 THE THEME ITSELF

真的 app、真的資料、真的字符底板（卡片上那些小色塊）。沙土路面板、米色卡片、樹冠機身、 寶可夢中心屋頂的橘用在選中狀態（排序鈕、MEGA 星、圖鑑分頁鍵）。 像素字型在 web preview 不會載入，所以拉丁字是系統字型——這點已知，實機才是準的。

還沒量、但可以在同一次實機驗收一起量掉 OPEN MEASUREMENTS

要量什麼為什麼重要
z-index 在 Lynx iOS 成不成立只有 C 需要它。量到成立，C 就從「押注」變成可選。
完全透明的 view 收不收得到觸控A／B 的「點外面關閉」靠它。web preview 已實測收得到。
絕對定位對非 .Root 祖先C 的錨定靠它（A／B 不靠）。
底板讓字符從 16px 變 18px 後的卡片列距.DexCell 的 201px 是實機量測值，不是推導值。變了就要一起改 src/state/rowMetrics.ts。

三個版本目前都在 src/ 裡，用 src/theme/menuVariant.ts 一行切換。 決定之後我會刪掉沒選上的兩個與那個切換檔，並把 spec 對齊。
